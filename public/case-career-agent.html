Local-first AI platform · public alpha Python 3.12 · FastAPI · React · TypeScript

Which openings actually make sense for this person, and why?

A local-first job intelligence application that goes further than keyword matching. It ingests postings from many sources, lets a model interpret the unstructured text, and keeps eligibility, lifecycle and scoring in deterministic code, so every recommendation traces back to the evidence that produced it.

01 · Deterministic where it has to be

The model is good at reading messy text: a job description that buries the location rule in paragraph six, a résumé that describes the same skill three different ways. It is not trustworthy for anything that must stay predictable. So the architecture draws that line explicitly.

Ingestion→Normalization→Structured extraction→Eligibility reasoning→Evidence matching→Search Fit→Explained recommendation
Eligibility
Gated before anything is scored
Hiring restrictions are kept separate from preferences. "Remote" does not mean worldwide, and a missing fact stays unresolved instead of being guessed.
Search Fit
Arithmetic, not a probability
A transparent score over configured preferences and observed posting facts, with the reasons and the missing information visible. The job title does not buy fit points.
Quotes
Verifiable by construction
Text quoted from a posting remains an exact substring of the source, so every explanation can be checked against the original.
02 · Evidence, not claims

The candidate profile is a living evidence base rather than a static résumé. A claim extracted from a document is a suggestion until the candidate reviews it.

Review
Extracted claims can be confirmed, edited, rejected or superseded. Importing text does not confirm experience.
Generation
A generated sentence never becomes confirmed evidence, in either module.
Export
Evidence-only export rejects edits that claim unsupported experience. A regression test covers exactly that: an edit claiming Salesforce experience the evidence does not support.
Why this matches. Reasons and missing facts are shown next to the score. Synthetic demo data.

04 · Local-first by design
Storage
Settings, jobs, notes and evidence live on the user's machine. Personal and demo data sit in separate directories.
Network
Collection is a deliberate user action. Optional AI providers receive content only when the user configures and uses them.
Telemetry
None implemented, in either product.

06 · Sources and recovery

More than 25 integrated adapters cover employer systems, remote boards and aggregators, plus manual import. Each source carries dated permission observations; request budgets, rate limits and link-back requirements are respected. A source that only provides metadata is never presented as a fully analysed posting.
